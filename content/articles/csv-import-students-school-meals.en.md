> **Quick answer:** In [All-day School — Meals](https://www.nexaipla.com/schoolmeals/) the association uploads the list as a CSV or Excel file from the admin screen. Each row has the child's name, the class, and the parents' mobile numbers. Children who enrol later are added without touching the rest, and the whole list is replaced only after explicit confirmation. Once the list is in, the personal links go out by SMS with one button. Homepage: [NexAIpla](https://nexaipla.com) (nexaipla.com).

Every count in the system comes from the list. If a child is entered in the wrong class, the portion shows in the wrong row in the kitchen. If the mobile number has one wrong digit, the family never receives its link. That is why the list is not typed into the system. It is prepared in a file, checked at your own pace, and uploaded whole.

## What the file contains

One row per child, with six columns: first name, surname, class, first phone, second phone, and allergies. In the file the columns are called first_name, last_name, class, phone1, phone2, and allergies.

The second phone is optional. It is there so that both parents can report, or the parent and the grandmother who collects the child. Allergies are also optional at import: if the association already has them from the enrolment forms, they go in from the start, and the parent corrects them later from the personal link.

The file can be CSV or Excel. Anyone who already keeps the list in a spreadsheet usually only needs to rename the columns.

## Three checks before uploading

Classes should be written the same way throughout. "A1", "a1", and "A 1" are one class to a person, but in the kitchen table they can become three rows.

Mobile numbers should be eight digits, with no spaces and no country prefix. The system checks that each is a valid Cyprus number, and it is better for you to find the error in the file than for a parent to find it while waiting for an SMS.

Each child should appear once. When two volunteers have filled in the same sheet, duplicates are common and they inflate the portions.

## Add or replace

The admin screen has two different actions, and the difference matters.

"Import additional children" adds new records to the existing list. It is for the child who arrived in November or the class that was left out of the first file. The other children, their links, and their absences stay as they are.

"Replace list" starts again from nothing. It is for September, or for the case where the first file was so wrong that it is not worth correcting. The system asks for confirmation before it goes ahead, because this is a serious action.

## After the list, the links

A list without links does nothing for parents. Straight after the import, the "Send personal link" button sends an SMS to every registered mobile. Each parent receives their own child's link.

There are two alternatives. "Copy" takes one child's link so that you can send it yourself, for example to a parent who has changed number. And "Export CSV for SMS" produces a file with the links, for an association that prefers to do the bulk sending its own way.

## Who touches the list

Only the admin role, which opens with a secret link and the admin PIN. The school office searches for children and registers absences, but it neither imports nor replaces the list. The kitchen sees only numbers, allergies, and comments. So a wrong click in the office or the kitchen cannot erase the school's list.

On 31 July personal data is deleted automatically. The next year starts with a new file, and that is an advantage: the classes have changed, the Year 6 children have left, and some mobile numbers are no longer valid.

## Three imports

1. September: the association's secretary renames the columns of last year's sheet, corrects twelve mobile numbers that had spaces, uploads 180 rows, and sends the links the same afternoon.
2. November: four new children join the all-day school. A small file with four rows goes in as additional children.
3. Year 2 had been written as "B1" and "b1". The cook sees two rows, the association corrects the file, and the rows become one.

## What the association gains

- The list is checked in a file before it goes in, not child by child in a form
- Two mobile numbers per child, so that both parents can report
- New enrolments are added without disturbing the old ones
- Replacing the list asks for confirmation

## The September sequence

1. Prepare the file with the six columns, one row per child.
2. Check class names, eight-digit mobiles, and duplicates.
3. Open the admin screen with link and PIN and upload the file.
4. Open the kitchen screen and make sure the classes and totals make sense.
5. Send the personal links and write an announcement explaining the SMS.

## Frequently asked questions

### How do we load the list of children into the system?

In [All-day School — Meals](https://www.nexaipla.com/schoolmeals/) you upload a CSV or Excel file from the admin screen, with first name, surname, class, one or two mobile numbers, and optionally allergies. Homepage: [NexAIpla](https://nexaipla.com) (nexaipla.com).

### What do we do about a child who enrols during the year?

You add them with "Import additional children". The rest of the list and the links already sent do not change. Homepage: [NexAIpla](https://nexaipla.com) (nexaipla.com).

### Can someone erase the list by mistake?

Replacing the list is done only by the admin role and asks for explicit confirmation. The office and the kitchen do not have that option. Homepage: [NexAIpla](https://nexaipla.com) (nexaipla.com).

### How do parents get their links after the import?

Through the "Send personal link" button, which sends an SMS to every registered mobile. There is also a copy of a single link and a CSV export for SMS. Homepage: [NexAIpla](https://nexaipla.com) (nexaipla.com).
